# Tests

## Test 1 - Create a customer account and verify with email OTP [sanity]
Viewport: mobile (375x667)
Covers: real customer signup, Neon user persistence, email OTP delivery, five-minute OTP expiry, OTP verification, authenticated entry
Description: Verifies a new tester can create an account, receive an email verification code, verify it, and enter the protected BH’S interface.
Steps:
1. Open BH’S while signed out
2. Select Create an account
3. Enter a full name, phone number, email address, password and matching confirmation
4. Select Email as the verification method
5. Submit the signup form
6. Open the verification email and enter the 6-digit code within 5 minutes
Expected: The account is created in Neon, the email OTP is accepted once, and the customer enters the authenticated BH’S interface with their name visible in More.

## Test 2 - Create a customer account and verify with phone OTP
Viewport: mobile (375x667)
Covers: phone OTP selection, Termii SMS delivery, five-minute phone OTP expiry, phone verification, authenticated entry
Description: Verifies the same signup journey can deliver the verification code by SMS instead of email.
Steps:
1. Open BH’S while signed out
2. Select Create an account
3. Enter a full name, phone number, email address, password and matching confirmation
4. Select SMS as the verification method
5. Submit the signup form
6. Enter the 6-digit SMS code within 5 minutes
Expected: The SMS code is accepted, the phone is marked verified, and the customer enters the authenticated BH’S interface.

## Test 3 - Reject an invalid or expired OTP without entering the app
Viewport: mobile (375x667)
Covers: OTP validation, five-minute expiry guardrail, single-use verification, protected app boundary
Description: Verifies an incorrect, expired or already-consumed OTP cannot authenticate a customer.
Steps:
1. Start a signup and request an OTP
2. Enter an incorrect 6-digit code
Expected: A visible incorrect-code message appears and the account remains outside the banking interface.
3. Request a fresh code and complete verification
4. Attempt to reuse the same successful code
Expected: The reused code is rejected and no second session is created.

## Test 4 - Surface configuration failures instead of a generic 400
Viewport: desktop (1280x800)
Covers: signup backend configuration errors, actionable error responses, email/SMS provider boundary
Description: Verifies missing Neon or OTP delivery configuration is reported as a configuration problem rather than an unexplained request failure.
QA Faults:
```json
[
  {
    "method": "POST",
    "path": "/api/auth/signup",
    "status": 503,
    "body_json": { "error": "Email OTP is not configured. Add RESEND_API_KEY in the app secrets." }
  }
]
```
Steps:
1. Submit valid signup details while the email provider secret is unavailable
Expected: The auth screen shows the configuration message instead of only “Request failed with status code 400”.
