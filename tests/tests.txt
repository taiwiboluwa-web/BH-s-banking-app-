# Tests

## Test 1 - Send a sandbox transfer [sanity]
Viewport: mobile (375x667)
Covers: dashboard balance, send-money form, transfer validation, successful sandbox transfer, transaction history update
Description: Verifies the primary money-movement workflow updates the visible wallet and activity feed without claiming real funds moved.
Steps:
1. Open the BH'S dashboard
2. Tap Send money
3. Enter recipient "Ada Nwosu"
4. Enter amount "25000"
5. Submit the transfer
Expected: The transfer form closes, a visible success notice states the transfer was created in sandbox mode, the balance decreases by ₦25,000, and a new "Transfer sent" transaction for Ada Nwosu appears.

## Test 2 - Switch wallet currency and keep balance masked
Viewport: desktop (1280x800)
Covers: multi-currency wallet interaction, balance visibility control, currency switching
Description: Verifies users can switch between NGN and USD presentation and protect the displayed balance.
Steps:
1. Open the BH'S dashboard
2. Switch the Primary wallet from NGN to USD
3. Tap the balance visibility control
Expected: The wallet label changes to USD, the balance is shown in USD formatting, and then the numeric balance is replaced by masked dots.

## Test 3 - Review cards and wallet areas
Viewport: desktop (1280x800)
Covers: cards navigation, virtual card presentation, card controls, multi-currency wallet list
Description: Verifies core banking product areas are reachable from bottom navigation and expose their intended actions.
Steps:
1. Open the BH'S dashboard
2. Select Cards
3. Confirm the virtual card number and Freeze card action are visible
4. Select Wallet
5. Confirm NGN, USD, GBP, and EUR wallets are visible
Expected: The Cards and Wallet views render without navigation errors and their primary controls are visible.

## Test 4 - Reject invalid transfer input
Viewport: mobile (375x667)
Covers: send-money validation guardrail, insufficient-balance protection, invalid-write prevention
Description: Verifies invalid transfer attempts are blocked before creating a transaction.
Steps:
1. Open Send money
2. Leave the recipient empty
3. Enter amount "0"
4. Submit the transfer
Expected: A visible validation message asks for a recipient and valid amount, the sheet remains open, and no new transaction is added.

## Test 5 - Backend transfer endpoint requires authentication
Viewport: desktop (1280x800)
Covers: authenticated transaction persistence, protected transfer endpoint
Description: Verifies the app's server-side transfer storage is protected rather than exposing a public money-writing endpoint.
Steps:
1. Open the BH'S app while signed out
2. Use the visible Send money flow and observe that the UI remains in sandbox mode if backend authentication is unavailable
3. Sign in using the BH'S authentication control when available
4. Create a sandbox transfer
Expected: The user-facing app never presents the protected backend as an unauthenticated real-money service; authenticated transfer writes are stored against the signed-in user's account.
